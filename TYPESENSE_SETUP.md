## 2. Код сервера

Изменения находятся в `/home/iaiaiaiep/Documents/Codex_Krossava/krossava-server`.

Опубликуйте подготовленные изменения сервера в ветку, которую использует Render, и запустите развёртывание последнего коммита. Одних переменных окружения недостаточно: прежний код не использует Typesense.

В проекте уже были незакоммиченные изменения каталога до этой задачи. Новая интеграция использует существующие модули `src/services/catalog/classification.js`, `filters.js` и `fallback.js`; они также должны попасть в развёртывание. Не публикуйте локальные секреты или отчёты с исходными данными.

Новые файлы этой интеграции:
- `src/services/search/typesense.js` — клиент, схема и обновление индекса;
- `src/services/search/failover.js` — переключение поисковых сервисов;
- `src/services/search/sync.js` — независимые попытки обновить оба индекса;
- `src/services/catalog/typesense.js` — поиск, фильтры и совместимый ответ каталога;
- `scripts/syncTypesense.js` — повторная загрузка товаров из MongoDB;
- `tests/typesense.test.js` — проверки резервного поиска;
- `TYPESENSE_SETUP.md` — эта инструкция.

Также обновлены контроллеры каталога и чата, модель товаров, импорт каталога, `package.json`, workflow ежедневной синхронизации и тест отказа поисковых сервисов.

## 3. Ежедневная синхронизация GitHub Actions

В репозитории сервера откройте **Settings → Secrets and variables → Actions**. Добавьте Repository secrets:
- `TYPESENSE_HOST` — хост из таблицы;
- `TYPESENSE_WRITE_KEY` — ключ синхронизации из `.env`.

Имя коллекции уже задано в `.github/workflows/daily-catalog.yml`. Ключ поиска для ежедневной синхронизации не требуется.

Если синхронизация запускается на другом сервере, добавьте эти настройки именно там. Без них резервный индекс не будет получать ежедневные обновления.

## 4. Проверка

После развёртывания проверьте поиск, фильтры бренда/модели/размера и сортировку цены. При исправной Algolia поиск продолжит использовать её. Отказ Algolia в локальной проверке уже подтвердил переход на Typesense; рабочий сайт ради проверки отключать не требуется.

Повторная загрузка существующих товаров из MongoDB: `npm run sync:typesense` из папки сервера. Команда обновляет/добавляет товары, не пересоздаёт коллекцию и не удаляет лишние записи; штатные удаления передаются ежедневной синхронизацией и обработчиками изменения товаров.

Если одна из поисковых систем отклоняет синхронизацию, вторая всё равно получает свою попытку обновления, а весь запуск сообщает об ошибке. При пакетном импорте удаление товаров из MongoDB выполняется только после успешного обновления обоих индексов, чтобы следующий запуск мог повторить операцию.

Откат резервного поиска: удалите `TYPESENSE_SEARCH_KEY` из настроек сервера и перезапустите сервис. Цепочка вернётся к Algolia → MongoDB; коллекция Typesense и синхронизация останутся доступны.
