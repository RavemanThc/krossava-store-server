# Импорт первых 10 фотографий из комментариев

Главное фото, цены, описания и доступные размеры остаются из Easydrop.
Дополнительные фотографии берутся **только из комментариев** к товару в Telegram.

## Отбор

- Сопоставление: первая буква + четыре цифры артикула (для подтверждённых префиксов MA/MB сохраняются обе буквы); визуально одинаковые кириллические буквы нормализуются.
- Сообщение с артикулом служит корнем обсуждения. Его главное фото исключается.
- Берутся первые 10 сообщений с фотографиями в хронологическом порядке внутри одной ветки, включая вложенные ответы.
- Если фотографий меньше 10, используются имеющиеся. Фотографии из других веток не добавляются.
- Если товар опубликован несколько раз, выбирается самая новая доступная ветка с фото.
- Повторяющиеся файлы среди первых десяти исключаются по SHA-256. Последующие фото вместо них не подставляются.
- Неоднозначные артикулы, отсутствующие родители и конфликтующие подписи попадают в отчёт.
- Новая галерея записывается целиком только после успешной обработки всей выбранной группы; повторный импорт не добавляет фото сверх десяти.

## Источник

Нужен JSON-экспорт **группы обсуждений** из Telegram Desktop вместе с фотографиями.
Экспортируйте нужный диапазон, включая исходные сообщения с артикулом и ответы.
Сохраните исходную структуру папок с result.json и photos.
Экспорт канала сам по себе не содержит комментариев группы.
Альбом без идентификатора группы или ссылки на родительское сообщение автоматически не сопоставляется по соседству.

## Запуск в папке backend

```bash
npm run import:photos -- --export "/path/discussion/result.json"
npm run import:photos -- --export "/path/discussion/result.json" --apply
```

Первый запуск проверяет сопоставление и наличие файлов, второй загружает их в Cloudflare R2 и сохраняет ссылки в MongoDB.
Отчёт: telegram-import-report.json. Настройки берутся из серверного .env: CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_R2_BUCKET_NAME, CLOUDFLARE_R2_ACCESS_KEY_ID, CLOUDFLARE_R2_SECRET_ACCESS_KEY, CLOUDFLARE_R2_PUBLIC_URL, MONGODB_URL.

Прямой импорт фотографий постов (`importTelegramPublic.js` и `uploadTelegramManifest.js`) отключён, чтобы не повторить ошибочную загрузку.

## Easydrop и публикация

`npm run sync:catalog -- --apply` обновляет название, категорию, цену, главное фото, описание и остатки без перезаписи галереи; товары без доступных размеров удаляются вместе с фотографиями. Без `--apply` выполняется только проверка.
Для ежедневного обновления используется GitHub Actions: см. DAILY_SYNC.md. Не включайте одновременно старый Render cron.
На Render нужны EASYDROP_FEED_URL, MONGODB_URL, ALGOLIA_APP_ID, ALGOLIA_ADMIN_KEY.

Для отображения галереи необходимо опубликовать обновлённые backend и frontend.
Экспорт Telegram — снимок истории: для новых комментариев нужен новый экспорт либо авторизованная интеграция Telegram API.

## Без ручного экспорта: Telegram API

В серверный .env добавляются TELEGRAM_API_ID и TELEGRAM_API_HASH из https://my.telegram.org/apps.
TG_API_KEY относится к боту заказов и для этого не используется.

Один раз выполните в своём интерактивном терминале `npm run telegram:login` и подтвердите вход.
Номер, код и пароль вводятся без отображения; сессия сохраняется в .telegram/session.txt (права 600, папка исключена из Git).
Не отправляйте коды, пароль или session.txt в чат.

После авторизации:

```bash
npm run telegram:collect
npm run import:photos -- --export .telegram/comments-export/result.json
npm run import:photos -- --export .telegram/comments-export/result.json --apply
```

Сборщик читает публикации только указанного канала и их ветки обсуждений. Он скачивает первые 10 фото комментариев по возрастанию времени; медиа самого поста не скачивается. Файл collection-report.json содержит пропущенные ветки.
Сбор и импорт проверены на реальных комментариях. Повторный запуск продолжает первоначальную выгрузку, пропуская уже собранные артикулы. Для нового полного снимка задайте новую папку через `--output .telegram/comments-export-new`; затем передайте её команде импорта.

Загрузка выполняется одновременно для шести товаров, внутри каждой галереи порядок сохраняется. Уже привязанные файлы повторно не загружаются.

Вход по QR без ввода номера: `npm run telegram:login:qr`, затем http://127.0.0.1:3106. QR обновляется автоматически; пароль двухэтапной проверки при необходимости вводится только на локальной странице.
