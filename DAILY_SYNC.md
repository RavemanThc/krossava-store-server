# Ежедневное обновление через GitHub Actions

Workflow: `.github/workflows/daily-catalog.yml`. Запуск каждый день в 00:00 Asia/Beirut с учётом перехода на летнее время. GitHub может задерживать запуск расписания; это не гарантия запуска ровно в секунду 00:00.

## Что делает

1. Загружает и проверяет полный XML Easydrop. Обновляет цены, описания, главное фото, размеры и количество существующих товаров; добавляет новые доступные товары.
2. Удаляет товары, у которых нет ни одного размера с количеством больше нуля, а также товары, исчезнувшие из полной выгрузки. Удаляет записи поиска Algolia.
3. Удаляет их изображения Cloudflare R2 из `krossava/telegram/<артикул>/`, включая старые версии. Файлы Easydrop не удаляет. Общие фотографии и артикулы активных товаров защищены.
4. Собирает размерные сетки из текстовых сообщений обсуждения Telegram: сопоставляет строго по артикулу, сохраняет последнюю опубликованную таблицу конкретной модели. Не подставляет общие сетки бренда. Если сетки нет, карточка предлагает уточнить замеры.
5. Для товаров без галереи получает первые 10 фото из комментариев Telegram и связывает по артикулу, включая MA/MB и кириллические эквиваленты. Существующие галереи повторно не скачивает. Если публикация ещё не появилась, повторяет поиск следующим запуском.

Очередь `catalog_asset_cleanup` в MongoDB сохраняет неудавшиеся удаления для следующего запуска. Поле `cleanupPending` и предупреждение в логе показывают отложенную очистку; сбой старого хранилища не блокирует загрузку новых галерей в R2. Пустой, повреждённый, менее половины прежнего каталога или удаляющий больше половины товаров фид блокирует изменение каталога и требует проверки источника. Параллельные запуски этого workflow запрещены. Другие задания обновления (например Render cron) следует отключить.

## Включение

1. Отправьте актуальный серверный проект, включая workflow, scripts, src/services, модели и package-lock.json, в **основную ветку** `RavemanThc/krossava-store-server`. Локальные `.env`, `.telegram/` и отчёты исключены из Git. Не добавляйте их принудительно.
2. Откройте Settings → Secrets and variables → Actions → New repository secret.
3. Добавьте значения из серверного `.env` под точными именами:

```
EASYDROP_FEED_URL
MONGODB_URL
ALGOLIA_APP_ID
ALGOLIA_ADMIN_KEY
CLOUDFLARE_ACCOUNT_ID
CLOUDFLARE_R2_BUCKET_NAME
CLOUDFLARE_R2_ACCESS_KEY_ID
CLOUDFLARE_R2_SECRET_ACCESS_KEY
CLOUDFLARE_R2_PUBLIC_URL
TELEGRAM_API_ID
TELEGRAM_API_HASH
```

4. Отдельный секрет `TELEGRAM_SESSION`: всё содержимое `.telegram/session.txt`. Это сессия Telegram-аккаунта, не токен бота заказов. Вставляйте только в GitHub Secret, не в YAML, Issues или логи. При отзыве сессии повторите авторизацию локально и замените этот Secret.
5. Actions → Daily catalogue sync → Run workflow. Сначала оставьте `apply` выключенным: отчёт покажет число новых/удаляемых товаров без изменений. Затем запустите с `apply` включённым и проверьте зелёный статус и артефакт `catalogue-sync-report`. По расписанию `apply` включён автоматически.

MongoDB должна принимать соединения от выбранного GitHub runner; аккаунту нужны запись в каталог и коллекцию очереди. Cloudflare R2 нужны права чтения, записи, перечисления и удаления объектов бакета. Algolia нужен ключ с правами записи и удаления в sneakers_index. Ключи и права бота заказов не используются.

## Локальные команды

```
npm run sync:size-charts      # Проверка размерных сеток без записи
npm run sync:size-charts -- --apply # Сохранение размерных сеток
npm run sync:daily             # Только проверка актуального фида и плана
npm run sync:daily -- --apply  # Обновление, удаление, сбор и загрузка недостающих фото
```

Обновление непосредственно меняет MongoDB/Algolia/Cloudflare R2, без ежедневного коммита и деплоя сайта. Обновлённый код API и frontend с галереей нужно один раз опубликовать отдельно. Кэши сайта обновятся по существующим срокам обновления.

Отчёты GitHub хранятся 14 дней и не содержат credentials или Telegram-сессию. При сбое запуск отмечается красным; уже завершённые операции можно безопасно повторить. Workflow и Secrets **не активируются от создания локального файла**: необходимы публикация и настройка репозитория.
